## 2026-10-22 · Open Notebook 导入与问答跑通

经用户选定，在既有 Codex 云端通过 Docker Compose 运行 Open Notebook 与 SurrealDB。固定源码和镜像，worker 并发 1，关闭可选 Docling/Crawl4AI，不下载本地大模型。合成 PDF 用于冒烟，另行导入 3 篇原始论文；合成数据不计入成果。

3 篇下载、上传和读取均为 200，哈希与本机输入一致，提取 50,134 / 61,337 / 59,970 字符。主要章节可识别，但有空格丢失和重复标题，图表与公式未逐页核对。

MiniMax 接入时，容器 CA 信任问题通过只读提供既有可信 CA bundle 解决，保留 TLS 验证和代理。首次原版生成返回 `length`，正文仅 350 字符。只对该模型与中国区地址传入 `reasoning_effort=low`、`max_retries=0`，保持 8192 上限，先检查构造参数再生成。之后单篇与综合均返回 `stop`，为 1,460 和 3,056 字符。三次共 108,597 tokens，来自会话 usage，不是费用。

证据：[云端导入](open-notebook-cloud-check.json)、[模型运行](open-notebook-minimax-check.json)、[适配说明](history-summary.md)。

## 2026-10-22 · 将完整生成与科学审定分开

关键剂量、暴露时长、LC50、置信区间和来源归属抽查基本对应原文。但 *Cyprinodon variegatus* 的中文名称不可靠，综合“肝脏或发育毒性”归纳过宽，部分断言缺少紧邻引用。全文返回只表示生成完成。

由此形成分层标准：文件可获得 → 输入未变 → 解析可读 → 模型完整回答 → 关键事实核对 → 用户实际流程。各项逐一确认，不能相互替代。

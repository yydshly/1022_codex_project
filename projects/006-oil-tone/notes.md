# 006 · oil-tone 研究记录

## 2026-10-21 · 从能力到实现细节

讨论依次确认了项目的能力、场景、与普通提示的区别、约束执行方式以及逐条规则的实际影响。最终研究重点是：约束如何进入 AI 的任务，如何改变具体编辑决定，哪些检查是程序实际实现的。

### 源码结论

- SKILL.md 共 46 行，正文 23 条：4 条基本目标、6 条内容组织、7 条语气句子、2 条形式、4 条复核。
- 名称和描述用于宿主识别；实际加载依赖宿主。没有模型服务代码。
- 主要约束是指令。规则经常包含条件和例外，不宜视为禁词表。
- 一个目标会在目标、操作、复核三个位置出现，例如 A1/C4/E3 对自然语法的重复要求。
- agents/openai.yaml 只有显示名称、描述、颜色和默认提示。
- tone_lint.py 只有标准库依赖，16 组正则，扫描可见文字，输出 WARN。没有替换、评分、模型调用或失败重试。
- Markdown 三反引号代码围栏、行内代码、部分 script/style 内容不参与匹配。该预处理不是通用 Markdown/HTML 解析器。
- 发现 WARN 后 main 仍返回 0，因而不是质量门禁。

### 完整改稿案例

固定 8 条虚构事实，构造包含宣传、含糊步骤、事实冲突与限制缺失的原稿。改写由本次助手依据 Skill 完成。网页将先前逐处分析合并为 21 个不重叠标记，覆盖标题、背景、身份、时长、体验范围、反馈、步骤、格式、因果、数据、推广、功能承诺、备份范围和结尾。

原稿 535 字符，成稿 612 字符（包含空白、Markdown 和教学说明，采用 Python len）。补充的内容来自事实底稿，不是自由生成的经历。稿件更长，是因为必要步骤、测试条件和限制被补齐。

计算核对：(100 - 35) / 100 = 0.65，表示耗时下降 65%，不等于处理效率上升 65%。

### 实际检查

Python 3.10.11；固定上游自检 PASS。原稿 9 条 WARN，涉及 4 行；成稿 0 条。扫描并没有发现时长矛盾、指标含义错误或附件导出范围夸大，后者由事实核对发现。

详见 examples/lint-results.json。这不是人工盲评、模型 A/B 或真实产品性能测试。

### 网页实现

静态 HTML/CSS/JS，无外部字体、依赖或在线 AI 请求。构建脚本从 canonical content.json 和原样上游快照生成 data.js，核对 23 个规则 ID、21 处唯一且不重叠的原文片段、原始文件哈希和实际检查结果。每张规则卡完整显示对应原文行；用户可以检查研究概括是否准确。

网站的交互是研究成果的阅读方式，不是源库本身提供的产品界面。

### 完整提示词

根据用户要求，将 23 条规则整理为 prompts/oil-tone-writing-prompt.txt，加入任务类型、读者、场景、材料、原稿、输出方式以及交付要求。A1—D2 和 E1—E2 保留原意；E3 说明可以连读或朗读检查；E4 仅在已有脚本并能运行时使用，普通对话没有脚本时依照 E1—E3 自查，不能声称程序检查通过。

提示词含完整来源和 MIT 许可，标明它是本研究的整理版本。打包器校验 A1—E4 共 23 个唯一编号，并将同一份 UTF-8 文本写入网页数据与下载文件，避免展示、复制与下载之间出现版本差异。网页新增“提示词”锚点、一键复制、只读全文框和下载入口。

### 一图总结

使用内置 ImageGen 生成原创信息图，把能力、上下文指令机制、五组规则、程序检查、场景、意义与边界放在同一画面。进行一次局部箭头修订，明确可选脚本从改稿阶段分支，并将提醒送回复核，随后交付。

最终 PNG 为 1536×1024，关键中文、五组规则数量和边界已经目视核对。不是上游截图，也没有增加模型效果或性能评测。完整生成与修订提示词、来源和文件哈希保存在 assets/ 中。

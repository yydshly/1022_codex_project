# 原有风格如何定制与引导

原有的 Algorithmic Sublime 应作为主档案保留。它的辨识度来自真实实体、计算结构、明确转化关系、参与构图的大字与画面情绪共同组织，而不只来自某种颗粒或固定配色。依据为固定版本的 [SKILL.md](https://github.com/xianxie6/algorithmic-sublime-poster/blob/846fac0a9fc247b480f71c9846c83815d2edfe41/SKILL.md) 与 [style-system.md](https://github.com/xianxie6/algorithmic-sublime-poster/blob/846fac0a9fc247b480f71c9846c83815d2edfe41/references/style-system.md)。

网页现在以 [原风格主档案](http://127.0.0.1:8033/003-algorithmic-sublime-poster/#prompt-lab) 为默认定制主线，之前的诗性材料、水墨、有机曲线放到“跨风格旁支”中。原有作者三例、十四张独立成图、情绪与材料实验、十三种 Canvas 处理均保留。本轮没有新增图像生成；新增的是原风格的描述、引导、配方和导出流程。

进一步加入了 [情绪引导档案](emotion-guide.md)，作为主体与风格定制之前的核心入口。21份起点可组合主副情绪，并将目标、故事、光色、数据节奏与返修要求载入主档案；固定规则继续保留。完整JSON升级到版本2，包含情绪来源与修改状态。

## 两层约束

| 固定视觉规则 | 这次可以调整的表达 |
| --- | --- |
| 主体真实、可辨认，保留脸、姿态和关键外形 | 人物、产品、植物、动物等具体主体及其识别中心 |
| 主体与计算结构存在清楚的边界或空间关系 | 局部分解、进入信息空间、扫描与分析标本 |
| 数据沿轮廓、透视、动作或光线组织 | 字符、像素、点云、扫描；同语法的体素与线框探索 |
| 模块化大字参与构图，保留文字与脸的安全距离 | 标题内容、语义断行、横竖版与阅读轴线 |
| 光色服从情绪，安静与密集区域有层级 | 奶油暖色、黑白青蓝、明亮天空；克制、标准或密集信息场 |

这些“固定”指网页会在指令与 JSON 中持续保留规则，不是模型的硬性数学约束，也不保证每次都执行到位。改变情绪不会自动改变其余字段，使用者需要逐项校准光线、材质和隐喻；页面只给出部分确定性的组合提示，没有语义识别或自动评分。

将计算结构全部换成纸片、墨色或装饰曲线，通常已经进入另一个风格方向；如果想保留原风格，这些材料最多用于有明确理由的少量混合，并应检查实体与数据的关系是否仍然清晰。

## 一次定制的顺序

1. 写希望观众感到什么、避免什么，例如温暖而有生命力，避免冰冷与破碎。
2. 确定主体和必须保留的脸、姿态、材质、产品结构。
3. 给计算语言一个理由，例如“生命被系统读取”或“动作成为连接世界的信息”。
4. 选实体与数据的关系，再选一种主要计算语言，指定发生区域与轨迹。
5. 调光色、画幅与强度；标题沿视线、动作或留白边界组织。
6. 附上角色清楚的参考图：主体图约束身份与外形，风格图说明视觉语法。
7. 看实际输出，按具体偏差返修，持续保留原有核心。

三份预设分别借温暖人物、深色科技、横向动作案例说明不同配方。旁边显示的是作者既有结果，**不是新生成结果，也不是本次界面配方已经得到验证**；组织出的指令不是作者当时的实际完整指令。横向动作原例还发生角色重设计，边界说明与完整原图均保留。

## 示例：把原风格用于一朵花

> 目标是温暖、有生命力的自然展览海报。保留橙色花朵的花心、左侧花瓣、弯曲茎秆和自然触感；以“生命被重新编码”为计算隐喻。只让右侧边缘逐步转为取自原色的像素与少量点云，沿生长方向延伸。使用奶油纸与柔金光，大号模块化像素标题《自然仍在生长》与弯曲茎秆呼应。保持克制留白，避免全图马赛克、无关界面与爆炸碎片。

这段示例说明如何在温暖情绪下保留原有视觉语法，不代表新增已生成作品。已有的花朵成图仍按各自真实生成记录展示，不把纸片版本改称原风格的严格复现。

## 返修时怎么拉回原风格

| 观察到的偏差 | 下一轮具体要求 |
| --- | --- |
| 像全图滤镜 | 缩小转换区域，恢复完整一侧，要求边界沿轮廓连续 |
| 像普通摄影，风格不明显 | 恢复可读的字符、像素、扫描或点云关系，并让标题参与构图 |
| 像装饰画或水墨画 | 恢复真实材料、计算结构和模块化标题；删除替代这些关系的主导装饰 |
| 信息太乱 | 只留一种主要机制、一层辅助结构和一个视觉焦点，降低覆盖范围 |
| 画面情绪被压没 | 保持主体光色与识别中心，先调范围、密度和留白，再决定是否更换手法 |

保留原风格的可见依据、修改理由和正反例，能逐渐形成团队共享的个人视觉规范。正式一致性评测仍应跨主体、跨情绪并重复生成；网页中的参数比例只是设计目标。

## 网页实现与数据边界

`web/app.js` 中的 `originalCore` 与 `originalPresets` 保存主档案规则和预设；原有提示词编辑器移到风格档案主入口。下载 JSON 包含五条规则、当前完整配置、风格参照来源和生成指令，`generated` 固定为 `false`。页面不调用图像模型、不上传图片、不持久保存草案。

`web/extensions.js` 将数字计算语言送入主档案，六种材料语言送入旁支编辑器；`web/direction-studio.js` 补齐烟雾与液态选项。原有三份跨风格档案保存在 `assets/styles/profiles.json`，不混称为原库的内置风格。

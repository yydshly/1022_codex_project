# 003 · Algorithmic Sublime Poster：研究笔记

## 2026-10-21 · 建立研究记录

- 研究问题：这是独立生成算法，还是风格与提示词流程？风格是否集中？示例实际保留了什么？如何用网页说明其能力与价值？
- 上游版本：`846fac0a9fc247b480f71c9846c83815d2edfe41`，GitHub API 核对 `main` HEAD 一致。
- 环境：Windows，Python 3.10.11，Node.js 22.15.0。静态页面无需安装前端依赖。
- 文件核查：完整树包含 README、SKILL、style-system、入口 YAML、媒体 NOTICE 与三张示例，没有独立模型、训练或绘图程序，也没有独立 LICENSE。
- 媒体核查：逐张阅读完整前后对比；本地原件记录尺寸与 SHA-256，网页只用 CSS 裁切结果区域，不改动图片文件。
- 关键观察：南瓜案例保留暖色并调整人物细节；彩珠案例把材质与像素联系；动作英雄案例发生角色重设计和标题变更，不能作为原角色保真转换的证据。
- 当前结论：设计规范、提示词组织、工具调用要求和检查流程构成核心实现。场景建议与价值判断来自规范推导，没有量化质量或成稿率实验。
- 网页交互：三案例切换、输出/完整对照、放大弹窗、四步原理、主体/标题/方式/配色/强度选择、复制/下载提示词与场景折叠。
- 集成：通过登记脚本分配 003，保留已有 001/002 记录；发布前打包带来源的原始媒体，不更改根汇总器。
- 待开展：真实图像生成、模型差异、中文准确率、身份一致性与印刷交付验证。

验证命令与浏览器检查结果见 [verification.md](verification.md)。稳定运行步骤已整理至 [README.md](README.md)。

## 2026-10-21 · 接入并实跑扩展样式

- 新增 13 种 Canvas 样式，覆盖数字结构与材料语言；所有程序为本研究原创，明确区分上游视觉方向与研究扩展。
- 加入原创 SVG 花朵作为统一输入，也支持作者原图和本地图片读取。
- 接入动作、密度、比例、速度、指针、滚动、四版式、PNG 导出、自动巡览和同源图谱。
- 实跑时发现 SVG 未声明固有宽高会使源矩形采样范围不完整，已明确 480 × 620 后重跑全部 13 种并导出。
- 浏览器各项操作与输出记录详见 [extensions.md](extensions.md)；PNG 原件与参数/散列保存在 `assets/extension-previews/`。
- 这一阶段尚未调用图像模型，不将程序处理效果解释为模型的保真度或生成成功率。

## 情绪海报修正

用户指出程序扩展缺少作者案例中的画面情绪。已将工作重心调整为完整海报创作：使用内置 ImageGen 工具实际生成《风有形》《向蓝而生》，保存原始 PNG、实际指令和生成记录；网页先展示成图及其情绪、光色、构图关系，再折叠展示 13 种算法示意。未自动执行上游 Skill，未测试输入保真或成功率。详见 [visual-quality.md](visual-quality.md)。

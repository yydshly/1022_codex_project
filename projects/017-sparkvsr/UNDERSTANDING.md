# SparkVSR：我们保留什么，暂缓什么

## 能力和效果

SparkVSR 将低清视频作为结构与运动约束，用少量高清关键帧提供细节，生成式重建更高分辨率的视频。核心是可控视频超分：用户先修好、审核少量关键帧，再传播其外观。

作者展示了边缘、文字、脸部与自然纹理改善及跨帧连续性。但模型在补充缺失信息，清楚并不能证明细节真实；4K 像素尺寸不意味着可恢复全部原生 4K 信息。

目前确认的是上游代码与论文描述、作者展示，以及本次静态网页可用。我们没有运行模型，不提供自己的效果结论、消费者显卡显存门槛、实时帧率或单位视频成本。

## 原理和技术分工

原视频编码为视频特征；关键帧经 PiSA-SR、图像 API 或外部编辑成为高清参考，再稀疏编码到对应时间位置。视频 Transformer 同时处理两类特征，经单步去噪与解码输出结果。

基于 CogVideoX1.5-5B-I2V 的视频模型负责时序建模；图像模型提供空间细节。两阶段训练先学压缩特征重建，再以像素、感知和帧一致性约束优化输出。参考移除训练支持无参考设置，参考强度控制依赖程度。单步去噪不是端到端实时保证。

## 可沉淀的五类技术与产物

1. **关键帧审核协议**：定义镜头、帧位置、参考版本、通过 / 返修及允许改变的区域，形成选帧清单与审核记录。目前只有方案。
2. **图像与视频模型适配层**：统一尺寸、参考缓存、模型来源及失败处理。单图修复模型可替换，但必须重新验证其产物是否适合传播。当前未实现适配层。
3. **可追溯控制参数**：保存参考位置、引导强度、输出尺寸、分块和随机种子；相同种子不等于跨设备 / 版本完全一致。当前未建立推理记录系统。
4. **双轨质量验收**：区分像素保真、感知质量、连续性与人工检查。核对脸、文字、细线、遮挡及镜头切换，不只看锐度或单一分数。当前只使用作者数据解释取舍。
5. **资源与交付调度**：评估分块、VAE 切片、CPU 卸载、取消和断点恢复。上游提供部分优化选项，稳定拼接与产品级恢复仍需实现和实测。

可以复用的是控制机制、工作流和评价方法；关键时序能力仍依赖训练好的视频模型。本仓库没有产出通用 SDK、网页推理工具或已验证的模型服务。

## 扩展场景及实施条件

| 场景 | 预期扩展 | 最先验证的问题 |
| --- | --- | --- |
| 老片与家庭录像 | 修复 / 上色关键帧，再传播 | 身份、字幕、颜色、长镜头漂移；保留原件 |
| AIGC 后处理 | 增加分辨率、统一纹理与角色外观 | 角色漂移、原有缺陷放大、速度和交付预算 |
| 人工精修接入视频 | 修图师修少量帧，传播到相关镜头 | 遮挡、新出现区域、镜头切换；补参考的成本 |
| 系列风格化内容 | 风格关键帧控制多段视频 | 身份、风格和跨镜头稳定性；不能从单一短片外推 |
| 剪辑 / ComfyUI 工具链 | 选帧、参考生成、审核、推理、对照、导出 | 服务、队列、取消、缓存、失败恢复与授权 |

老片修复、上色和风格迁移有作者示例；人工精修工具链、批量产品和剪辑软件集成是我们的设想，尚未交付。

## 当前决策

了解并留档，暂不深入研究。核心仍是模型的视频生成与重建能力；专项价值在于关键帧控制、空间先验与时间传播的分工，以及保真和观感的可调取舍。

本轮只发布静态理解页。未来有需求时，以短片、固定权重、人工审核和完整参数记录做小规模验证，再决定是否继续。不承诺真实细节完全恢复、任意视频稳定提升或实时处理。

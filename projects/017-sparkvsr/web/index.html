017 / GENERATIVE VIDEO SUPER-RESOLUTION

理解归档 · 未运行模型

把低清视频，
重建得更清楚。

以原视频约束运动和结构，用少量高清关键帧提供细节，再由视频模型生成式重建整段画面。

清晰度提升，包含模型对缺失细节的推测。输出更大、更锐利，不代表恢复了全部真实信息。

先看我们的理解 ↓看作者真实对比 ↗

当前决策：了解并留档，暂不深入研究或部署推理服务。

01 / UNDERSTANDING

先说清楚：能做什么，值得留下什么。

我们的判断是“有原视频约束的生成式重建”。这个项目的专项贡献，是让可编辑关键帧成为细节控制入口，并学习跨帧传播。

能力与效果

低清 → 高清重建

提高输出分辨率，补充边缘与纹理，并尽量保持帧间连续。可先修好关键帧，再让其他帧跟随。

默认宽、高各放大 4 倍；真实细节不能保证完全还原。
可沉淀的技术

控制与验收工作流

关键帧审核、单图修复与时序传播分工、参考强度调节、参数记录，以及保真 / 观感双轨评估。

目前沉淀为方案与理解，尚未形成自有 SDK 或模型服务。
后期扩展场景

修复与创作后处理

老片和家庭录像、AIGC 增强、人工精修接入视频、系列风格化，以及剪辑 / ComfyUI 工具链。

具体场景需要样片、成本和质量验证，产品集成尚未实现。
本次完成已有资料与讨论整理 · 引导图归档 · 静态网页发布未执行模型下载、推理、训练与性能实测

把“单张图修得好”和“整段视频保持一致”分工处理。图像模型先给出参考，视频模型再结合原始运动重建。

04 / 输出

高清重建视频

原始动作约束
＋补充外观细节

流程示意，非推理结果。缺失的高频细节来自参考图与模型学到的先验。

关键帧可以编辑

手动、随机或按 I 帧选取。先审核生成的参考图，避免将错误细节传播到其他帧。短片通常可先用首帧。

参考强度可以调

ref_guidance_scale 为 0 时不使用参考，1 为标准引导，大于 1 更依赖参考。更强不表示更真实。

训练兼顾细节与时间

先在压缩特征空间学习传播，再在像素空间优化重建、感知纹理和帧一致性。随机移除参考也训练无参考能力。

看一层内部机制：稀疏编码、两阶段训练

原视频与关键帧分别编码。参考仅放入对应时间位置，其他参考位置填零；两路特征融合后，视频模型从原视频特征出发重建。

第一阶段学习压缩特征的重建；第二阶段解码回像素，加入 MSE、DISTS 与帧一致性约束。单步去噪描述模型步骤，不构成端到端实时保证。

04 / WHAT WE CAN REUSE

可沉淀的是机制和流程，
关键能力仍依赖模型。

下面是候选工程产物，当前只完成理解整理。没有把这些机制包装成已经实现的 SDK、自动化平台或可脱离权重的算法。

01

关键帧审核协议

记录镜头、帧位置、参考版本、审核与返修；少量关键帧先过人，再进入批量处理。

可形成：选帧清单 / 审核记录
02

图像模型与视频模型适配

统一尺寸、参考缓存、来源和错误处理，将“修一张图”与“稳定传播”分开。

可形成：参考生成器接口
03

可追溯的控制参数

保存参考图、位置、引导强度、分块、输出尺寸与种子；更换版本后重新验收。

可形成：任务配置 / 版本记录
04

保真与观感双轨验收

结合像素、感知、视频指标与人工对照；重点查脸、文字、遮挡、细线和镜头切换。

可形成：样片集 / 验收报告
05

分块与资源调度

评估时间 / 空间分块、VAE 切片和 CPU 卸载；产品层再补取消、缓存与失败恢复。

可形成：处理队列 / 资源预算

06 / BOUNDARIES

边界与成本，
在使用前说清楚。

  • 细节可能由模型推测，文字、脸部和纹理可能改变。
  • 参考图的错误可能被传播，参考更强不等于更真实。
  • 输出 4K 表示像素尺寸，不代表恢复全部原生 4K 信息。
  • 真实性要求高的用途需要逐项验证。

模型运行是另一项工程

上游依赖 Python 3.10+、PyTorch 2.5+、Diffusers、GPU 环境与模型权重。PiSA-SR 可本地运行，商业图像 API 可能收费。

支持分块、VAE 切片与 CPU 卸载，但速度、显存与拼接质量未在本机验证。作者训练用 4 张 A100，不等于推理的最低要求。

当前网页是静态理解页，不接收视频、不调用模型、不持有 API 凭据。
当前决策

了解并留档，暂不深入研究。

核心仍是模型的视频生成与重建能力；专项价值在于关键帧控制和时序传播。后续有明确需求时，先用短片验证质量与成本，再决定是否部署服务。

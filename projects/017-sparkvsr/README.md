## 我们的理解

SparkVSR 是**以原视频为约束的生成式视频超分辨率与修复框架**。原视频提供人物位置、运动、构图和时间变化；少量高清关键帧提供想要的外观与纹理；模型结合二者，重建整段高清视频。这里“更清楚”包含模型推测补充的细节，不能等同于恢复全部原始真实信息。

我们当前将其核心归纳为模型的视频生成与重建能力。专项价值是把少量可编辑关键帧变成控制入口，并学习跨帧细节传播。它值得保存为一种可控修复工作流，但当前没有明确的视频修复需求，因此先完成理解归档，不下载大模型、不部署推理服务、不扩展实验。

## 能力与效果

| 能力 | 输入与输出 | 效果及边界 |
| --- | --- | --- |
| 视频超分 | 低清视频 → 高分辨率视频；脚本默认宽、高各放大 4 倍 | 作者示例中边缘、文字、人物与自然纹理更清楚；分辨率尺寸不等于真实信息量 |
| 关键帧引导修复 | 原视频 + 少量修好的高清帧 → 连续重建视频 | 先审核参考图，再传播其细节，减少逐帧独立生成导致的纹理变化 |
| 无参考修复 | 原视频 → 模型自身先验支持的超分结果 | 作者主要作为备用与对比设置；不是最佳观感展示的默认选择 |
| 扩展编辑 | 上色、修复或风格化的少量关键帧 → 对应的视频 | 作者展示老片修复、上色和风格迁移；具体素材仍需独立验证 |

**作者评测，不是本机实测。** 论文表 1 中 UDM10 数据如下，指标均越高越好：

| 指标 | DOVE | SparkVSR 无参考 | SparkVSR + Nano-Banana-Pro 参考 |
| --- | ---: | ---: | ---: |
| PSNR / dB：像素保真 | 26.52 | 26.62 | 23.70 |
| CLIP-IQA：图像观感 | 0.5011 | 0.4303 | 0.5501 |
| DOVER：视频质量 | 0.5664 | 0.5494 | 0.6902 |

参考模式能提升观感评分，同时可能降低对真实高分辨率画面的像素接近程度。不能据此声称所有数据集、所有指标全面领先，也不能将质量评分当作事实准确率。真实动态对比请看 [作者演示](https://sparkvsr.github.io/comparison.html)。本页不把示意图当作实际处理结果。

## 原理：用原视频保结构，用参考帧补细节

1. **选关键帧**：手动指定、随机选择或提取编码 I 帧；短片可以先用首帧。
2. **修关键帧**：使用 PiSA-SR、Nano-Banana-Pro 或外部编辑，得到用户认可的高清参考。
3. **分别编码再融合**：原视频与稀疏参考映射到压缩特征空间。参考放在对应时间位置，其他参考位置填零。
4. **联合重建**：基于 CogVideoX1.5-5B-I2V 的视频 Transformer 利用两类信息，单步去噪后解码为视频。它从原视频特征出发，以原始结构和运动约束重建。
5. **调节参考影响**：ref_guidance_scale 为 0 时无参考；1 为标准引导；大于 1 更强地采用参考细节。更高不代表更真实。

训练先在压缩特征空间学习重建与传播，再在像素空间加入重建、感知及帧一致性约束。训练中移除部分参考，保留无参考能力。关键源码为固定版本的 [推理入口](https://github.com/taco-group/SparkVSR/blob/a082284b80005bb5615c0f5f5f5ed66650b1b1e7/sparkvsr_inference_script.py)、[参考处理](https://github.com/taco-group/SparkVSR/blob/a082284b80005bb5615c0f5f5f5ed66650b1b1e7/finetune/utils/ref_utils.py)和 [ComfyUI 文档](https://github.com/taco-group/SparkVSR/blob/a082284b80005bb5615c0f5f5f5ed66650b1b1e7/ComfyUI-Spark/README.md)。本次没有源码级运行验证。

## 可沉淀的技术

| 候选沉淀 | 可以复用的方式 | 当前完成度 |
| --- | --- | --- |
| 稀疏关键帧的人工审核入口 | 审核少量参考，记录修改、位置与版本，再进入视频处理 | 已整理工作流；未实现审核工具 |
| 单图修复与时序传播分工 | 图像模型生成参考，视频模型负责传播与运动约束 | 已整理适配思路；未接入模型 |
| 参考强度调节 | 把参考图、位置和引导强度作为可记录的控制参数 | 上游已有参数；本仓库未实现推理封装 |
| 保真与观感双轨评估 | 同时保存像素、感知 / 视频指标及人工检查记录 | 已整理指标含义与作者数据；未建立自有评测集 |
| 分块与资源调度 | 按性能预算评估时间分块、空间切块、VAE 切片和 CPU 卸载 | 上游提供选项；本机显存、速度、拼接质量尚未验证 |

这些是**可借鉴的机制与工程流程**，不是我们已经提取出的 SDK，也不是脱离模型权重就能工作的通用增强算法。具体建议与条件见 [完整理解](UNDERSTANDING.md)。

## 后期可扩展的使用场景

| 场景 | 可以提供的能力 | 需要补齐的条件 |
| --- | --- | --- |
| 老电影与家庭录像 | 修复关键帧后传播清晰纹理；进一步尝试上色 | 保存原件，核对人物、文字与重要细节，验证长镜头稳定性 |
| AIGC 视频后处理 | 增加输出分辨率和纹理一致性 | 核对角色与风格漂移，测量尺寸与时长成本 |
| 人工修图接入视频 | 人工修好关键帧，再传播到相关镜头 | 处理新出现区域、遮挡与镜头切换；不能保证任意编辑都可靠传播 |
| 系列风格化内容 | 用统一风格关键帧指导视频重建 | 验证身份、色彩、纹理及多镜头稳定性 |
| 剪辑软件 / ComfyUI 工作流 | 接入选帧、参考生成、审核、推理、对照验收与导出 | 模型服务、排队取消、失败恢复、资源预算和许可核对 |

产品集成是我们的扩展设想，尚未落地。当前不把它定位为取证、医学、测量等需要真实细节准确恢复的工具。

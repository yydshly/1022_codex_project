# 研究说明：能力、原理与增量

依据：AmazingAng/old-coder，提交 `a0eb529d393a1cb3ccc564e32b2104e7e75c7a29`，研究日期 2026-10-22。

## 核心价值

本研究的理解：它把“需要什么证据才接受修改”整理成可重复使用的工作制度。对象是能读指令、写文件、调用工具的 coding agent，以及负责确认需求和验收的人。代码与测试仍由 Agent 编写，检查仍需已有工具执行。

Skill Markdown、领域参考与模板表达工作要求；示例脚本是 Python 限流器的具体落地，不是装上就能跨语言运行的独立测试平台。自然语言规则的遵循取决于 Agent，机器强制约束则来自脚本、CI 与合并规则。

当用户只提功能要求时，它可帮助补上规格、故障模型和证据。当用户通过完整提示、AGENTS.md、测试与 CI 已覆盖相同要求时，增量可能较小。没有真实模型 A/B 实验，不量化质量提升或时间节省。

## 六阶段

1. SPEC：具体输入输出、负向约束、风险、工具/依赖/隔离计划、修订。通常人先确认；自主执行可继续，但需说明未获确认。确认减轻同一作者定义正确性的相关性，不证明需求完整。
2. RED：先让测试在旧行为或桩上失败。导入错误不充分验证行为；立即通过的测试应辨明行为已存在还是断言无效。
3. GREEN：实现当前契约，运行相关全套测试。
4. REFACTOR：整理结构，保持行为断言；测试结构另行重构并验证测试力度。
5. GAUNTLET：实际运行适用层，失败阻止完成；记录基线，遗漏、缺工具和替代执行不能标通过。
6. EVIDENCE：需求映射到测试，固定源码与环境，持久化脚本，用最后源码的新运行交付结果。

信任有四个对象：规格是否覆盖重要行为、断言是否识别错误、检查器是否可靠、报告是否准确对应当前源码。上游案例表明四者都可能出问题。

## 检查之间的关系

- 覆盖率说明执行过，不说明预期正确或断言有效。
- 变异测试检验当前测试能否抓住人为错误。手写列表受作者思路限制；AST 工具也有等价变异，需解释。
- 随机/属性测试取决于生成策略与不变量。例如“一定不超限”让一律拒绝也通过，需可用性或独立参考模型。
- 真实执行补充测试桩以外的入口，不代表所有部署环境均已验证。
- 负向对照只确认一个已知坏样本能被拒绝，不证明检测完整。
- 领域层不可被通用百分比替代：数据库事务、真实并发压力、回滚与性能预算应按实际风险验证。

## 四类实验的选择

**库存通知幂等**：重复、交错和中断可具体触发，结果能用库存与效果次数表达。真实系统还需事务、唯一键、隔离级别、消息确认、外部副作用。网页模型事务不能证明数据库持久性。

**滑动限流**：边界与身份隔离有明确预期，可结合参考模型、边界变异和随机序列。网页沿用上游闭窗口：恰好 W 时仍计入，超过 W 才过期。真实业务需确认自己的窗口定义。

**多租户权限**：自己能读不足以证明授权，应测别人的资源不能读、伪造租户不生效、列表与导出不绕过。示例用 403，真实服务也可按策略用 404 隐藏存在性。

**API 兼容**：200 不表示旧客户端继续工作；要保留请求、字段、类型。新增响应字段通常依赖消费者忽略未知字段，严格 schema 等仍需检查。网页不是完整兼容性分析器。

## 原始限流器

每个 key 的获准请求时间存在 deque，请求时清理过期项、判断额度并追加。锁覆盖读时钟、清理与额度变更，避免并发顺序破坏。周期 sweep 清理闲置 key。存储边界是时间范围，不是 distinct key 数量绝对上界；窗口内无限不同 key 是已接受风险。

README 写 41 测试，详细报告写 50。详细报告含 9 个源码绑定测试；本机仅执行应用与属性文件得到 41 项。这解释两组计数范围，但 README 摘要未明说范围；网页保留原数字与差异。

## 可选独立复核

协议先给任务契约、已确认 SPEC、精确源码和入口，盲测后再提供证据草案。复核者不修复，由人评价重要发现。通常两轮为上限，更多轮需明确决定；六轮是历史探索。

新上下文只减轻任务上下文相关性，相同模型仍可能共有偏差。案例原 A/B 设计失败，不能估计准确率或误报率。约 55 万 token 是该次探索成本，不可推广。

## 我们可复用的部分

先找当前流程缺口，保留已有工具与基线；把不能发生的损失写成场景；让关键检查以失败退出码阻止完成；保存复跑入口、源码与环境；分别记录 n-a、unavailable、substituted 和 unverified。适合有明确验收、出错代价较高的任务；探索与审美需求需要人的判断，不宜无差别套高风险流程。

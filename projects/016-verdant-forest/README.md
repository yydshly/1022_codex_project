## 我们的理解

- **能力与效果**：用规则生成并组织三维植物，组合地形、材质、风动、阴影和薄雾，形成能自由漫游和自动导览的森林。近看有枝叶与林下细节，远看有树冠体积和空间层次。
- **可沉淀技术**：植物几何与参数种子、确定性空间布局、共享网格与实例化、空间分区和距离细节、GPU 风动及阴影同步、深度约束的空气散射、确定性镜头与逐帧采集。
- **后续扩展**：自然主题展厅、庭院与旅宿导览、交互叙事网页、自然氛围短片。每个方向还需要内容制作、授权核对、目标设备预算和产品集成。

更完整的取舍、建议沉淀模块及扩展条件见 [UNDERSTANDING.md](UNDERSTANDING.md)。当前交付是研究网页与技术分析，通用资产导出工具、可复用 SDK 和与 009 的直接代码整合仍未完成。

## 网页提供什么

1. **能力介绍**：自由漫游、植物结构、风动、五镜头导览和逐帧输出。
2. **真实效果**：三张上游浏览器采样图，可切换、放大和键盘浏览；另有白桦树皮改进前后的离线对照。
3. **原版体验**：按需嵌入作者当前托管的完整森林，可以切换自由漫游 / 自动导览、全屏和停止；始终提供新窗口入口。
4. **五个原理实验**：多尺度地形、曲面叶片、共享树形批量摆放、时间与相位风动、距离细节。均由本研究独立编写，清楚标注为 Canvas 教学示意。
5. **渲染分析**：从几何与 PBR 材质，到太阳阴影、接触遮蔽、单次空气散射与最终合成。
6. **价值说明**：自然主题体验、Web 3D 工程学习、确定性镜头创作；同时说明授权、设备预算和集成条件。
7. **证据索引**：固定版本源码链接、原始验证记录和可下载来源清单。

## 本地运行

在仓库根目录执行：

```powershell
python projects/016-verdant-forest/scripts/package_web.py
python projects/016-verdant-forest/scripts/package_web.py --check
node --check projects/016-verdant-forest/web/app.js
node --check projects/016-verdant-forest/web/data.js
python scripts/project_catalog.py check
python -m http.server 8016 --bind 127.0.0.1 --directory projects/016-verdant-forest/web
```

然后访问 `http://127.0.0.1:8016/`。图集和教学实验使用本地资源；原版体验才需要访问作者站点。运行原版需要浏览器支持 WebGL 2 和可用的图形环境，网络、第三方站点和浏览器策略可能影响嵌入。外部页面的 load 事件只表示页面载入，不作为森林渲染成功或帧率通过的证据。

`assets/` 保存唯一的上游材料；`package_web.py` 验证原始哈希与作者采样记录后，生成被忽略的 `web/assets/` 发布副本。现有 Pages 工作流在汇总站点前调用该脚本；根 `build_site.py` 只复制 `web/`，不发布研究目录。

## 工作原理与代码位置

| 层次 | 源码 | 实现方式 |
| --- | --- | --- |
| 场景组织 | `app/forest/engine.ts` | Three.js WebGLRenderer、相机、灯光、资源创建与销毁、渲染循环 |
| 地形 | `math.ts`、`surfaces.ts` | 多层噪声叠加高度；对实际地形三角形插值，统一落地位置 |
| 植物几何 | `trees.js`、`botanical-refinement.js`、`understory.js` | 弯曲分枝、逐渐变细的管状网格、弯折叶片和各类林下植物 |
| 布局与 LOD | `vegetation.ts`、`distant-trees.ts` | 固定随机流、间距与小径规则、共享网格、InstancedMesh、空间分区和远景池 |
| 风动与表面 | `materials.ts` | 时间 / 位置相位 / 高度权重控制顶点；树皮与苔藓加入局部变化；深度材质同步变形 |
| 光影后处理 | `volumetrics.ts` | 场景颜色与深度、太阳阴影、屏幕空间接触遮蔽、40 步单次散射、双边上采样及调色 |
| 镜头 | `cinematic.ts` | 8 + 6 + 6 + 5 + 5 秒五镜头，平滑插值相机和注视点 |

所有链接在网页中固定到研究提交。程序化生成不等于生态生长模拟；风动公式也不是流体力学模拟。

### 如何控制性能成本

- 乔木先生成八个变体，重复使用几何；实例拥有不同位置、旋转、缩放与色调。
- 桌面、quality=1 时，近景树木分区的高 / 中 / 低细节切换使用 24 m、56 m 水平距离阈值；移动端与其他植物采用不同阈值，远处还使用额外共享池。
- 地面草随距离降低密度；体积散射在较低分辨率计算，组合时尽量保留叶片边缘。
- 实际帧率低于 27 时逐步降低内部像素比，质量下限为 0.64。这是质量降级策略，不是帧率保证。

## 效果与验证范围

- 三张原始浏览器采样图与作者台账中的 SHA-256 完全匹配，采样时间为 8、25、28 秒。
- 作者台账记录 7,155 棵树；其余大量草、蕨类、苔藓等是生成数量，不代表每帧全部可见，也不代表单独绘制调用。
- 树皮对照图是作者离线材质检查输出，网页明确标注。
- 作者另行记录 AMD Radeon 780M 上的 1920 × 1080、720 独立帧、30 秒影片；24 fps 为编码播放节奏。逐帧采集耗时 405.08 秒，不能推导交互帧率。
- 本研究的 Canvas 示例独立于原版；不把它的流畅度、三角形数或实例数当作上游性能测量。
- 本轮在内置浏览器中实际载入作者当前托管的原版自动导览，观察到 canvas `data-status=ready` 和真实森林画面；未测量交互 FPS。原版报告了两条非致命的 X3595 着色器导数警告，本研究网页未出现脚本错误。
- 本轮具体静态、浏览器与响应式验证结果见 [verification.json](verification.json)。

## 应用价值

| 方向 | 能带走的知识 | 要补的工作 |
| --- | --- | --- |
| 自然主题展示 / 空间叙事 | 多层植物、漫游相机、空气感与构图 | 自有内容、叙事、设备适配和加载体验 |

建议从一小块林下环境开始，先完成预算测量，再添加树皮、苔藓和体积光。当前没有整体代码授权，技术分析和模块设计可以先作为学习参考；完整改造发布前应确认适用授权。
